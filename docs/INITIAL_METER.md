# 簽約日與初始電表

房客資料 →「其他聯絡與房間資料」可記錄本次合約的「簽約日」及「初始電表（度）」。簽約日與起租日分開；未提供資料保留空白，不以 0 或起租日代填。

新房客第一個電費期別，以簽約日與初始度數作為前期日期與電表。之後沿用上一電費期的實際紀錄。例如 8/15 簽約、初始 1,000 度，9/1 抄到 1,120 度，第一期使用 120 度、電費 600 元；11 月改用 9 月已確認的電表。

正式 Google 端須在既有專案新增 `InitialMeter.gs`，並更新 `SiteBridge.gs` 及 `CashSettlement.gs`（保留既有收款與結算功能）。新欄位只在管理人明確儲存時新增，保留鎖定、原值比對、公式／合併格保護。不要用本 repo 舊 starter 覆蓋 live Rent_Demo。

管理人使用既有「預覽本月初始化／初始化本月」，才會把第一期前期電表與日期寫成月份快照；只讀取房客、帳務、報表不會改寫試算表。初始化會檢查同房、同名房客、簽約日是否位於本次抄表區間，並保留已有本期度數、收款或受公式保護的紀錄，提示人工核對。簽約日等於本期抄表日不計入該次結算。若月份缺漏或同一月份換了多位房客，需先核對分段帳務，不自動猜補。

新欄位不會回頭重算歷史帳單。月份快照寫入原「前期電表」「前期抄表日期」欄，後續計費仍使用這些欄位。初始化會先沿用現有後端的初始化行為；正式接線前，須用實際 MonthlySetup／RentalAccounts 原始碼及表頭副本驗收：前期欄位可寫、公式引用正確、重跑不覆蓋既有紀錄。若原欄位為公式則停止該房初始帶入，保留公式並提示，不能以關閉保護的方式處理。

Pages 僅提供虛構唯讀範例：401 房 8/15 簽約、初始 1,000 度，9 月顯示簽約日起算；506 房示範初始 0 度。正式試算表／Apps Script 尚未部署或修改，須隨正式站接線驗收。
