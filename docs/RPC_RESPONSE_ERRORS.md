# 正式站帳務讀取回應保護（2026-10-25）

使用者回報正式站每月帳務偶爾顯示 `Unexpected token '<' ... is not valid JSON`，並確認執行。原因可確認為某次回應不是可解析的 JSON；僅憑訊息無法判定 HTML 來自 Cloudflare、登入導向或其他上游服務。

## 本次修改

- 共用 `workspace-transport.js` 與舊帳務相容入口 `billing-transport.js` 使用一致的回應檢查；送出 Accept: application/json。
- 區分 401／明確登入導向、403 權限或安全驗證、429 請求過多、5xx 服務暫時異常、非 JSON／無效 JSON／回應結構錯誤，以及網路連線失敗。
- 明確登入失效沿用現有登入提醒，不自動跳頁，以保留畫面輸入；不把一般 HTML 擅自判定為登入過期。
- 非 JSON 錯誤不顯示原 HTML、網址、解析器片段或內容。可解析的既有業務錯誤（如資料衝突）繼續顯示原有訊息。
- 沿用「重新讀取」按鈕與未儲存草稿保護；沒有自動重試、重新整理、重新登入或資料清空。未知操作結果提示先讀回核對、勿重複送出，包含年度準備／初始化。
- 沒有新增 API、後端寫入、權限變更或 Google 資料修改；不需更新 Apps Script 或原 Web App 部署。Demo 同步共用傳輸程式，仍唯讀。

這項修正避免不正確的 JSON 解析錯誤直接出現在畫面，改善失敗辨識與安全恢復；不代表已定位或消除偶發上游 HTML 的根因。若仍發生，可依時間、畫面提示及不含私密回應的 HTTP 狀態繼續核對，不需提供原 HTML 或金鑰。

## 驗證

兩個傳輸入口合成測試：HTML 200、無效／空 JSON、登入導向、401、403、429、502／503、網路失敗、合法業務錯誤與 0／false 成功值、手動再次讀取恢復。每次操作只一個請求，不外洩回應內容或 URL。實際帳務編輯元件在儲存遇 HTML 時保留後五碼草稿、不自動重送，草稿仍阻擋重新讀取。另跑原帳務與工作區回歸，CI 驗證正式及 Demo 建置／唯讀。
